# SafeChill VPN

Семейный VPN на двух нодах Timeweb Cloud без панелей, докера и подписок. Один `install.sh`,
пять скриптов, systemd. Собран в сентябре 2026 под текущее поведение ТСПУ.

```
                    ┌──────────────── NL exit (Амстердам) ────────────────┐
  клиент ──443──►   │ xray  VLESS + XHTTP + REALITY  (SNI = свой домен,     │ ──► интернет
  клиент ──8443─►   │ xray  VLESS + TCP + REALITY + vision (SNI icloud)     │
  клиент ──udp──►   │ AmneziaWG 3.1 (kernel module)                         │
                    │ nginx 127.0.0.1:8444 — «настоящий» сайт для REALITY   │
                    │ vpn-health.timer — проверки раз в минуту + Telegram   │
                    └───────────────────────────▲───────────────────────────┘
                                                │ XHTTP+REALITY (один пул соединений)
  клиент ──443/8443─► RU entry (Москва): xray, REALITY под yandex.ru, всё → NL
```

- **Основной путь**: XHTTP + REALITY на 443. Одно долгоживущее HTTP/2-соединение с xmux, без бурста
  TLS-рукопожатий, которые ТСПУ с июня 2026 замораживает. SNI — свой домен, REALITY «крадёт» локальный
  nginx с настоящим сертификатом, поэтому IP, SNI и сертификат совпадают.
- **Резерв**: TCP + REALITY + xtls-rprx-vision на 8443 под `gateway.icloud.com`. Не зависит от домена.
- **Быстрая полоса**: AmneziaWG 3.1 (HeaderProtection, ContentPadding, RandomTrailers, DisableCookies)
  для домашнего провода. На мобильном и в режиме белых списков ненадёжен, поэтому не основной.
- **RU-вход**: для «белых списков» мобильного интернета. Клиент ходит на российский IP с SNI
  `yandex.ru`, нода пересылает всё в NL по XHTTP+REALITY. Пользователи одни и те же, конфиг RU-ноды
  рендерит и заливает NL-нода.
- Торренты через xray режутся (`BLOCK_TORRENT=1`), приватные сети заблокированы, BBR включён.

## Установка (NL-нода, Ubuntu 24.04, root)

```bash
git clone https://github.com/egr4045/vpn-installer safechill && cd safechill
cp vpn.env.example vpn.env      # DOMAIN обязателен, остальное по вкусу
nano vpn.env
./install.sh
```

Домен должен указывать на IP ноды **без прокси** (серая тучка в Cloudflare) — иначе Let's Encrypt не
выдаст сертификат. Если DNS ещё не готов, `install.sh` поставит самоподписанный сертификат, VPN
заработает, а health-check раз в минуту будет напоминать про DNS. Поправил DNS — просто перезапусти
`./install.sh`.

`install.sh` идемпотентен: секреты генерируются один раз в `/etc/safechill/secrets.env`, пользователи
живут в `/etc/safechill/users.json` и `/etc/safechill/peers/`, всё остальное перерисовывается.

## Запасной выход и смена IP

```bash
setup-exit2.sh 1.2.3.4 nl2.example.com   # вторая нода-выход: те же секреты, люди и AWG-пиры
```

RU-вход получает балансировщик xray: пока основной выход отвечает на пробы (observatory, каждые
20 секунд), весь трафик идёт в него, иначе автоматически в запасной. Подписки содержат оба выхода,
ключ `amnezia-x2` даёт запасной выход в AmneziaVPN.

«Сменить IP» в боте (или `rotate-ip.sh`) берёт у Timeweb новый IPv4 для основной ноды, переписывает
DNS, конфиг RU-входа, все ссылки, подписки и ключи. Нужны `TW_API_TOKEN` и `TW_SERVER_ID` в vpn.env.
Старый IP остаётся как служебный; `/dropip <ip>` отпускает лишний, но Timeweb при этом
перезагружает сервер.

## RU-вход

На чистой Ubuntu 24.04 в России ничего ставить не нужно, всё делает NL-нода:

```bash
setup-ru.sh 200.165.237.236 yandex.ru   # ssh root@<ru-ip> должен работать с NL-ноды
```

## Люди

```bash
add-client.sh egr        # печатает ссылки, кладёт всё в /root/clients/egr/
del-client.sh egr
vpn-status.sh            # сервисы, порты, сертификат, AWG-пиры, RU-нода, health
update-xray.sh           # обновить xray на обеих нодах
```

В `/root/clients/<имя>/`: `nl-xhttp.txt` (основной), `nl-tcp.txt` (резерв), `ru-xhttp.txt` и
`ru-tcp.txt` (для белых списков), `awg.conf`, а также `nl6-*`, `ru6-*` и `awg6.conf` с IPv6-адресами
нод для сетей, где IPv6 фильтруют слабее. QR-коды `*.png` ко всему. Выход в интернет с NL-ноды идёт
по IPv6, если у сайта он есть (`EGRESS_PREFER=ipv6`), иначе по IPv4.

## Клиент: AmneziaVPN 5.0.1.5+ (Android, iOS, Windows, macOS)

Один клиент на всё: в нём родной AmneziaWG 3.1 и с версии 5.0.0.5 XHTTP+REALITY с XMux.

1. `+` → «Импорт» → вставить `vless://…` из `nl-xhttp.txt` (или отсканировать `nl-xhttp.png`).
2. Так же добавить `nl-tcp.txt` и `ru-xhttp.txt`: между серверами переключаемся вручную, если основной
   вдруг не подключается.
3. AmneziaWG: `+` → «Импорт» → файл `awg.conf` или QR `awg.png`.

Если XHTTP в Amnezia капризничает: Happ, v2rayTun, Streisand (iOS), v2rayNG (Android) едят те же
`vless://` ссылки. Для AWG есть официальное приложение AmneziaWG. Часть клиентов удалена из
российского App Store, нужен зарубежный Apple ID.

## Telegram-бот

Тот же бот, что шлёт алерты, принимает команды от админов (`TG_ADMIN_IDS` в vpn.env), в личке или в группе.
Команда одна — `/users` (она же `/start`). В чате два типа сообщений, и они не смешиваются.

**Живое сообщение** — вся навигация, всегда правится на месте. Главный экран: одной строкой состояние нод
из `health.json`, люди кнопками (🟢 = в сети сейчас), ниже «Добавить» и «Подробно». Сколько людей и кто
в сети отдельными строками не пишется — это и есть кнопки. Тап по человеку превращает сообщение в его
экран: профили кнопками (• = что показано), «Удалить», «← Люди». Ничего не плодится.

**Карточка** — то, что пересылается человеку: фото с QR, три шага и сама ссылка или ключ в подписи, и
только клиентские кнопки — «iPhone / Android / ПК» и «Скопировать ссылку». Callback-кнопок в ней нет
совсем (пересылка их всё равно срезает), поэтому пересланная копия остаётся полной. В чате живёт одна
карточка: следующая заменяет предыдущую. Шаги ведут к копированию, а не к QR — свой собственный экран
телефон не отсканирует, QR остаётся для второго экрана. Ключ Amnezia (~870 символов) влезает в подпись
(на шапку уходит ~140 из 1024 единиц); если конкретный ключ длиннее, он приходит отдельным файлом `.vpn`.
Ключи `vpn://` собирает `bin/amnezia-key.py` в нативном формате клиента, по одному протоколу на ключ,
чтобы QR оставался читаемым.

**Подробно**: ноды, порты, сертификат, диск, память, аптайм, сайты, последние инциденты — всё из снимка
`health.json`, поэтому мгновенно, без проб. Издатель сертификата и число инцидентов показываются только
когда с ними что-то не так. Там же «Проверить сейчас» и «Сменить IP»; после смены IP кнопка
«Отпустить ‹старый IP›» ведёт к подтверждению, командой это набирать не нужно.

Скрытые команды на случай надобности: `/add Имя`, `/del Имя`, `/qr Имя [clash|ru|nl|awg|x2]`, `/status`,
`/newip`, `/dropip 1.2.3.4`. Опасные действия спрашивают подтверждение, прогресс («⏳ Создаю…»)
редактируется в результат, не-админ по кнопке получает всплывашку, а не сообщение в чат. Деньги бот не
показывает. Тексты держатся той же дисциплины, что алерты: что делать, без объяснений и без повторов —
одно и то же состояние всюду называется одинаково. Словарь общий с алертами: 🇳🇱 Амстердам, 🇷🇺 Москва,
🛟 Запасной.

По умолчанию людям выдаётся профиль ClashMi — подписка `/c/<token>` для клиентов на ядре mihomo
(`bin/clash-sub.py`). На экране выбора ровно три пункта, и каждый — цепочка с автопереключением, так
что тупика не бывает: **⚡ Авто** (вход через Москву, дальше Амстердам, запасной выход, TCP, IPv6),
**🚀 Макс. скорость** (AmneziaWG на оба выхода, а если UDP не проходит — уходит в «Авто») и
**🛟 Резерв** (те же серверы без московского хопа, когда сломан именно вход). Российские сайты
напрямую, DNS over HTTPS, fake-ip в 198.18.0.0/16.

Домены, чей CDN отвечает кэшами внутри российских провайдеров, матчатся по имени **до** `GEOIP,RU`
(список `FORCE_PROXY`): из Москвы `www.tiktok.com` → AS29076 RU, `tiktokcdn`/`ttwstatic` →
AS51369 RU, а API TikTok — Akamai в Швеции, поэтому по одному `GEOIP,RU` приложение висело
полузагруженным. Там же YouTube с `googlevideo` (кэши GGC у провайдера — как раз те, что душат),
Meta, X, Discord, OpenAI. Запасной вариант — ключ Amnezia через RU-вход: он
переживает белые списки, а падение выхода компенсирует балансировщик на самой ноде. Подписка
`/s/<token>` (все xray-серверы одной ссылкой) по-прежнему генерируется для сторонних клиентов, но в
боте не показывается.

Сервис `safechill-bot.service`, только стандартная библиотека Python, long polling.

## Логи

Все ноды пишут xray на `loglevel: info` с `dnsLog` в journald, ротация 8 дней / 4 ГБ (`templates/journald-99-safechill.conf`,
разносится `render.sh` на вход и на запасной выход). Объём измерен: ~580 тыс. строк в сутки на выходе, ~430 тыс. на входе.

Имя человека и адрес назначения встречаются вместе **только на входной ноде** — выход видит релейный
трафик как одного пользователя `relay-ru`. Поэтому «кто» берётся оттуда, а «что ответили» — с выхода.

`bin/vpn-log.py` (на выходной ноде) опрашивает все три журнала одним запросом:

```
vpn-log.py --host tiktok --since -3h            кто и когда ходил на подходящий хост, и что упало
vpn-log.py --user Dima --since "2 days ago"     что человек открывал и где сломалось
vpn-log.py --errors --since -2h                 только настоящие сбои
vpn-log.py --user Egor --host youtube --raw      сырые строки за сводкой
```

Фильтр выполняется на дальней ноде, так что неделя журнала не едет по сети. Нормальное закрытие
потоков (`CANCEL`, `client disconnected`) сбоем не считается — иначе настоящие тонут в нём 20:1.

Чего в логе нет и не будет: **кодов HTTP**. xray проксирует TLS не раскрывая его, так что результат
всегда на уровне соединения — установлено, отказ, таймаут, DNS не разрешился. «Устройство» тоже не
различается: у человека один UUID на все устройства, отличаются только адрес и порт источника.

## Мониторинг

`vpn-health.timer` на Амстердаме раз в минуту: REALITY на 443 отвечает как сайт, 8443 отдаёт сертификат
icloud, awg0 поднят, nginx жив, интернет по IPv4 и IPv6, сертификат (порог 14 и 3 дня, продление не
чаще раза в час), диск (80 и 95 %), память, Москва и запасной отвечают, перезагрузка сервера. Упавшее
перезапускает и пробует снова; если ожило — молчит (три самовосстановления за час дают одно 🟠). Алерт
уходит после двух неудачных прогонов подряд. Деньги не отслеживаются и нигде не показываются.

Формат алерта: `эмодзи Нода · что случилось по-человечески`, техническая деталь, что сделано
автоматически, 👥 кого из людей касается, → что делать админу. Уровни: 🔴 люди не могут пользоваться и
🟠 деградация — со звуком; 🟡 предупреждение заранее, 🔵 инфо — тихо.

**Один инцидент — одно сообщение.** Когда всё чинится, тот же самый алерт редактируется в
«🟢 снова работает» с временем начала, конца и длительностью простоя, а внизу курсивом остаётся, что
именно было. Новых сообщений при восстановлении не приходит. Каждый день в 09:00 MSK — ☀️ дайджест:
инциденты за сутки, сайты, сертификат, диск, кто был в сети; не пришёл дайджест — Амстердам лежит.
Если Telegram недоступен (нет интернета, перезагрузка), сообщения ждут в спуле и уходят потом с
пометкой о задержке; id отправленного сообщения хранится в `health.state`, чтобы правка нашла его.

Популярные сайты (YouTube, Google, Instagram, Telegram, ChatGPT, X, Facebook, Discord, TikTok,
WhatsApp, GitHub, Netflix) прощупываются с ноды параллельно; набор недоступных, стабильный два прогона,
даёт одно сообщение с человеческими названиями. Снимок всего этого — `/var/lib/safechill/health.json`,
из него бот рисует экран «Подробно»; журнал инцидентов — `incidents.log` рядом.

Москва (`vpn-health-ru.timer`) сообщает только о том, как Амстердам виден из России, и различает
четыре случая: нет интернета на самой Москве (🟠), IPv4 Амстердама заблокирован, а по IPv6 отвечает
(🔴, менять IP), Амстердам недоступен целиком (🔴), заблокирован только :443 по SNI (🟠). Свой
xray Москва перезапускает молча — о нём сообщит Амстердам, дублей нет. Чат для алертов: `TG_CHAT_ID`
в vpn.env, иначе бот привязывает алерты к первому чату, где ему написал админ.

## Деньги (Timeweb, сентябрь 2026)

| Нода | Тариф | ₽/мес |
|---|---|---|
| NL exit | Cloud NL-15 (1 vCPU / 1 GB / 200 Мбит) + IPv4 | 710 |
| RU entry | Cloud MSK 40 (2 vCPU / 2 GB / 1 Гбит) + IPv4 | 1000 |

Трафик у Timeweb не тарифицируется. Серверы создаются только с IPv6, IPv4 добавляется отдельно
(`POST /servers/{id}/ips`). После удаления сервера IPv4 остаётся платным floating IP — удалять руками.

## Что не так и что дальше

- `.ru` домен могут отозвать: тогда ломаются только сертификат и «настоящий сайт», Reality-8443 и AWG
  работают дальше. Клиенты ходят по IP, DNS им не нужен.
- Планы: IPv6-ссылки для клиентов, взаимный мониторинг нод, проверка доступности популярных сервисов
  с NL-ноды одним сообщением, перебор IP RU-ноды под белые списки операторов.
